# fixtures/ — the C2 cross-language oracle

`fh_fixture.json` is the frozen Python oracle for `src/spherical_pair.rs`, consumed by
`tests/spherical_pair_fixture.rs`.

| | |
|---|---|
| schema | `ssolink.c2.fh_fixture/3` (barycentric; `/1` and `/2` were heliocentric) |
| source of truth | **ssolink**, `kernels/spherical-pair/fixtures/fh_fixture.json` |
| generated by | ssolink `_fh_fixture.py`, from `_fh_probe.py` / `_fh_grid.py` / `kernels/spherical-pair/grid.py` |
| sha256 | `06d73796a958fe5aa26e819aacd288586ce7176594271a253aa7bcc119b44728` |
| frame / units | barycentric ecliptic J2000; AU, days, radians, JD TDB |
| `mu` | `2.9630927493968080e-04` = `spacerocks::Origin::SSB.mu()`, bit-for-bit |

**This file is a copy, not a second source.** It is checked in here so the Rust tests need no
Python, no ephemeris and no network — the observer positions come from astropy's builtin
ephemeris, so recomputing them in Rust would mean reimplementing something that is not under
test. To refresh it, regenerate in ssolink (`python _fh_fixture.py`, `--check` to verify the
checked-in file still reproduces bit-for-bit) and copy the result here.

🔴 Both sides must assert the same properties. ssolink's `tests/test_fh_fixture.py` and this
repo's `tests/spherical_pair_fixture.rs` deliberately overlap: **a fixture only one side checks
is not an oracle.** ssolink also carries a test that fails if this copy drifts from the source
of truth.
